## Known risks
- **Coverage debt (HIGH).** Real coverage is **64.46% lines / 52.39% funcs** (measured 2026-10-01 after the `bin/`, test-suite and prune work), not the 85.30% previously recorded here. That figure was produced by a run whose build was broken, which inflated the ratio by dropping the files that failed to load. Per AGENTS.md §4 rules 1-2 (threshold 80% lines), **Bolt and Refactor are currently blocked from acting on the majority of the codebase** and must hand off to Spec. Closing this gap is the highest-value Spec work available. The suite count is now honest — the valueless cases were pruned and the 4 auto-generated stubs were rewritten into real assertions on 2026-10-01. What remains weak is 11 suites whose assertions are only `.toBeDefined()`; they do exercise real construction paths, so they were kept, but they are candidates for Spec to strengthen.
- **Coverage measurement depends on a populated `bin/`.** Measuring without the Llama.cpp runtime yields 13 false failures and an invalid coverage number. Any agent reporting coverage must confirm `bin/` is complete first.
- **The Llama.cpp runtime is now fetched automatically (RESOLVED 2026-10-01).** `bin/` holds ~48 `llama*`/`ggml*` artifacts that `scripts/ensure_binaries.ts`, `native-build.yml` and `bundle_distribution.ts` never produced or downloaded — they had to be placed by hand, which is why `docs/TROUBLESHOOTING.md` §5b existed. `bun run fetch-llama` (`scripts/fetch_llama_runtime.ts`) now downloads the **pinned** release `b11146` asset `llama-b11146-bin-win-cpu-x64.zip`, **verifies its published SHA-256 before extracting**, and installs into `bin/`. Verified end to end: downloaded 17.7 MB, hash matched, extracted, and the full suite still reports 323/323 in ~35s. `ci.yml` runs it after `ensure-binaries`. Notes: (a) the upstream **stable** tag `v0.5.0` publishes only `nightly-tag.txt` — the binaries live on the nightly tag, which is why `b11146` is pinned rather than `v0.5.0`; (b) this is a deliberate third-party dependency, approved by the maintainer under AGENTS.md §4.7; (c) the asset is Windows x64 only, so the script reports and exits 0 on other platforms rather than failing; (d) **which version the previously hand-placed binaries came from is unknown** — they carry no version metadata, so the pin is a fresh baseline, not a match to the old files.
- **Auto-merge gate is live (RESOLVED 2026-10-01).** Auto-merge requires a branch protection rule (or ruleset) on the target branch enforcing a required status check: GitHub shows the auto-merge option "only on pull requests that cannot be merged immediately", and the repository-level "Allow auto-merge" setting is not accepted without one. The maintainer configured **classic branch protection** on `main` requiring the `validate-and-build` check from `ci.yml`, then enabled the setting. Note this repository deliberately has **no rulesets**, so `GET /repos/{owner}/{repo}/rulesets` returns `[]` and is *not* a useful check here — verify at Settings > Branches instead. Escalations of the form "Branch protection on main may not require the ci.yml status check" should no longer be raised; if they reappear, the gate has regressed.
- **The required check validates less than the full suite.** `ci.yml` runs on `windows-latest` and does **not** populate `bin/`, so it covers compilation plus the suites that tolerate a missing Llama.cpp runtime. If the SLM suites ever start requiring that runtime in CI, the now-required `validate-and-build` check will block **every** merge. Revisit before that happens.
- **Stale test scratch directories (MITIGATED).** Three suites create `.psa_*` scratch dirs in the repo root; when a test fails before its own teardown the dir survives. `tests/test-setup.ts` (registered via `bunfig.toml` `preload`) now sweeps them once per run. Removal is best-effort — a directory held open by a spawned child process on Windows may survive, which is why a leftover is expected occasionally and is not a failure.
- **`src_native/hub/hub.exe` untracked (RESOLVED 2026-10-01).** It was tracked *despite* `.gitignore` line 52 (`*.exe`) because it was committed before that rule existed, bloating every clone by 24.9 MB. Confirmed it is a pure build artifact by moving it aside and verifying `bun run ensure-binaries` rebuilds it to the same size via `go build`. Removed with `git rm --cached` (the file stays on disk and `go build` regenerates it); `git check-ignore` now reports `*.exe` for it. **Consequence for CI:** `ci.yml` gained a `setup-go@v5` step (Go 1.25, matching `src_native/hub/go.mod`) plus `bun run ensure-binaries` BEFORE the tests, so the binary is built rather than committed. `analyzer.exe` is still tracked, so the Rust branch of that script stays skipped — if it is ever untracked too, that step exits 1 until a Rust toolchain is added. Git history still contains the old binary; only new clones benefit from the size reduction.
- **Test suite is ~86% stable, not fully deterministic.** Measured 7 full runs on 2026-10-01: 6 exited 0, and one exited 1 after taking 46.7s instead of the usual ~32s. The failure was not captured by name, but the correlated slow run points at a load/timing-sensitive suite. Re-run before escalating a single failure; treat a failure that disappears on re-run as flake, not regression.
- **`bun test --coverage` numbers are only trustworthy with a complete `bin/`.** See the Llama.cpp risk above. The historical 85.30% figure was produced by a build-broken run and should not be used as a baseline for any agent decision.
